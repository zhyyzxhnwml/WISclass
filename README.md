# 上课啦

> **别人告诉你什么时候上课；上课啦告诉你什么时候出门、这节课讲了什么、期末该复习什么。**

一个面向**一所学校**、适配**荣耀 200** 的 Android 课程中枢 App。课程表只是入口，真正解决的是「上课前 → 上课中 → 下课后」的整条链路。

> **学校相关配置不入库。** 仓库是公开的，所以「哪所学校」只存在于本机的
> `school.properties`（已被 `.gitignore` 忽略，模板见 `school.properties.example`），
> 构建时注入到 App 里。教务域名、统一认证域名、校园根域名、明文放行清单都在那里。
> 连 `network_security_config.xml` 也是构建时按这份配置生成的 ——
> 否则域名会留在公开仓库里。

## 定位

- **自用项目**：不发布、不盈利、无账号体系、无广告。
- **纯本地**：除「从教务系统抓课表」这一步需要校园网外，**AI 能力全程离线**，飞行模式下可用。
- **全内置模型**：ASR + LLM + OCR + 向量模型全部打进 APK，装上即用，零 API 费用。

### 端侧 ASR 是怎么落地的

真机环境探测决定了技术路线：

| 资源 | 可达性 | 结论 |
|---|---|---|
| GitHub / HuggingFace | ❌ 不通（**2026-10-06 复测已通**，见下） | sherpa-onnx 的预编译 AAR 当时拿不到 |
| **ModelScope** | ✅ 通 | 模型走这里下（官方 `iic/SenseVoiceSmall-onnx`） |
| **`com.microsoft.onnxruntime:onnxruntime-android`** | ✅ 通 | **推理引擎换它** |

所以最终是：**ONNX Runtime + SenseVoice ONNX，fbank / LFR / CMVN / CTC 全部自己实现**。

```
录音 .m4a (16kHz 单声道 AAC)
  → MediaCodec 解码成浮点 PCM
  → AudioChunker 按静音点切段（约 28 秒一段）
  → Fbank（手写：去直流 → 预加重 → 汉明窗 → FFT → mel → log）
  → LFR 拼帧（7 帧 × 80 维 → 560 维）
  → CMVN（am.mvn）
  → SenseVoice ONNX → ctc_logits [T, 25055]
  → CTC 贪心解码 → 剥控制标记 → 句子切分
  → 带时间戳落库（transcript_segment）
```

**没有可用的 Android fbank 库，这部分是手写的**，所以做了金标准验证：
用 `kaldi_native_fbank`（与 sherpa-onnx 同源）在 Python 侧产出基准，
把窗函数、mel 滤波器组、FFT 功率谱、fbank、LFR、CMVN 各层的中间量
全部固化成测试资源，Kotlin 实现逐层对齐（误差 7.9e-05，即 float32 精度极限）。
生成脚本在 `tools/sensevoice/`，过程与踩到的坑都记在它的 README 里。

**四个不报错但会让识别悄悄变差的坑**（都已实测敲定并写进注释）：

| 坑 | 正确做法 |
|---|---|
| 采样量纲 | 必须 ×32768（int16 量纲）。少了 CMVN 工作点偏 3.0，结果看着还行实则退化 |
| 去直流 vs 预加重 | 先去直流，后预加重。顺序反了误差从 8e-05 涨到 4.9 |
| 预加重首点 | `x[0] -= 0.97·x[0]`（首点取自身），不是保持不变 |
| mel 刻度 | `1127·ln(1+f/700)`，不是 HTK 的 `2595·log10` |

### 「该出发了」的推算规则（零配置）

不要求标地图，只用两条现成信息：**要不要换楼**（从教室名解析楼栋前缀）+ **课间有多长**。

| 情况 | 提前量 |
|---|---|
| 同楼 | 5 分钟 |
| 换楼 | 15 分钟 |
| 楼栋信息拿不到（如纯数字教室） | 10 分钟（默认） |
| 课间比提前量还短 | 一下课就走 |

楼栋解析：`A-101` → `A`，`3B301` → `3B`，`体育馆` → `体育馆`，纯数字 `101` → **null**。
拿不到就退回默认值 —— 猜错会给出错误的提前量，比不给提示更糟。

校园 POI + 真实步行时间是后续增强，这版只做相对判断。

### 桌面小组件说明

`4×2`，展示今天的课 + 标出「进行中」/「下一节」，点击进入 App。

**刻意不做秒级倒计时**：MagicOS 对小组件刷新有节流，做倒计时会卡住不动，
反而给人「坏了」的感觉。刷新只靠两处驱动：组件自身的 30 分钟系统周期 + 每次打开 App。

### 0.9.0：从教务页面自动识别校历与作息时间

「第一周是哪天」和「每节几点上课」先前都要手填，而这两件事**填错了都不报错**：
校历错一周 → 整张课表的「本周有没有这门课」全判错；作息错 → 上课静音和
「该出发了」在错误时刻触发。所以改成从教务页面自动读。

```
课表页（已登录的 WebView）
  → 注入 JS 只做一件事：把页面可见文本原样带回 Kotlin
  → Kotlin 侧正则解析：「第X周」+ 各节次起止时间
  → 反推第一周周一 = 本周周一 − (X−1)×7
  → 摆出来给用户确认，点「采用」才写库
```

**解析全部放在 Kotlin 而不是 JS 里** —— 正则解析是最容易出错的一环，
写在 JS 字符串里没法单测，出错了只能靠猜。

**刻意不自动应用**：识别结果先显示在导入页（`当前第 5 周 → 第一周周一应为 2026-09-07`），
用户确认后才写入。错一周的代价太大，不能靠静默猜测。

| 能力 | 说明 |
|---|---|
| 当前周次识别 | `第N周` / `周次：N` / `当前周 N` 三种写法；超出 1~30 一律丢弃不猜 |
| 作息时间识别 | 分块（`第1-2节 08:00-09:40`）与逐节（`第3节 10:00-10:45`）都支持 |
| 分块拆分 | 只有分块数据时按每节 45 分钟推算拆分，**结果标红提示「需核对」** |
| 差异展示 | 只列真正不一样的节次（`第1节：现在 08:00-08:45 → 识别为 08:30-09:15`） |
| 全角容错 | `：～－` 等全角标点同样能识别 |
| 读不到时如实说明 | 页面文本长度为 0 → 「注入脚本可能没生效」；有文本但没匹配 → 「页面上没找到」 |

> 开发中被测试抓到一个真 bug：`第1-2节 08:00-09:40` 会被解析出**两条** ——
> 分块正则命中后，单节正则又在同一段里匹配到 `2节 08:00-09:40`，
> 凭空多出一条「第2节」把作息表写坏。修法是把分块已覆盖的区间记下来，单节匹配跳过。

### 0.8.2 修复：重新导入会丢光笔记的课程归属

两个相关联的问题：

| 问题 | 根因 | 修复 |
|---|---|---|
| 导入成功后**再也找不到导入入口** | 「导入真实课表」按钮只写在 `!state.hasData` 的空状态分支里，首次导入成功后就永远走不到了 | 顶部栏加常驻「导入」；设置页再加一个「课表导入与刷新」入口 |
| **重新导入会清空所有笔记的课程关联** | `note.courseId` 是 `ON DELETE SET NULL`，而 `replaceCourses` 是「全删再全插」——删课那一刻所有笔记的 `courseId` 被置空，且不可逆 | 改成只删「这次导入里已不存在」的课（按 `stableKey` 比对），并复用仍然存在的课程行 id |

> 第二个问题的杀伤力被第一个掩盖了：入口消失导致没人能重新导入，
> 所以这个数据损失一直没暴露。一旦补上入口，用户第一次重导入就会踩中。

### 0.8.0：接云端大模型做真正的 AI 摘要

端侧 LLM 走不通（见下节），所以改走**云端 OpenAI 兼容接口**，这也是设计里
`SummaryTier.EXTERNAL` 那一档。**没有引入任何 SDK** —— 就是 `POST /chat/completions` 一条请求。

| 能力 | 说明 |
|---|---|
| AI 摘要配置页 | 设置 → 模型管理 → 去配置 AI 摘要 |
| API Key 加密存储 | AES-256-GCM，密钥由 Android Keystore 保管，**不写进代码、不上传** |
| 模型列表动态拉取 | 从 `/v1/models` 拉，**不写死模型名**（聚合平台的模型会增删改名） |
| 测试连接 | 一键验证地址 / Key / 模型名，HTTP 错误码翻译成人话 |
| 强制 JSON 输出 | 要点 / 术语 / 疑难点 / 作业 / 自测题，结构化才可被下游消费 |
| 长录音 map-reduce | 超过 6000 字先分段压缩再归并，不截断也不撑爆上下文 |
| 失败自动降级 | LLM 挂掉不影响转写，退回规则抽取，**并把失败原因写进摘要里** |

**实测确认的接入信息**（未使用用户 Key，靠 401 判断端点存在）：

| `https://api.agnes-ai.com/v1` | 404 ❌ |

> ⚠️ **隐私边界**：这是本项目唯一会把数据送出手机的功能。录音与转写仍只存在本机，
> 但生成摘要时这节课的**文字**会发到用户填的服务地址。不接受就别开——
> 关着也能用，摘要退回规则抽取。配置页上有醒目的红字提示。

### ⚠️ 端侧 LLM 为什么走不通（已逐条验证）

之前语音模型只能在「点转写」时被动下载，看不到状态、不能主动下、不能删；
而 AI 摘要模型根本不存在，界面上却写着「未接模型」，被读成了「模型没下载」。

设置 → 模型管理，把这两件事彻底分开：

| 项 | 状态 | 能做什么 |
|---|---|---|
| 语音识别模型 | 已实现 | 下载 / 暂停续传 / 删除（省 230MB） |
| AI 摘要模型 | **功能尚未开发** | 刻意不给下载按钮 —— 文件下下来也没有代码加载它 |

### ⚠️ 端侧 LLM 目前的真实障碍

写摘要需要本地大模型。**把可行路径逐条验证过，结论是现在做不了**，原因很具体：

| 需要的东西 | 情况 |
|---|---|
| `onnxruntime-genai-android`（跑 ONNX LLM 的引擎） | **Maven 镜像上不存在** |
| `com.google.mediapipe:tasks-genai` | **不存在** |
| 预编译的 llama.cpp Android 包 | 社区包里只有 JVM 版（`de.kherud:llama`），不含 Android so |
| NDK + CMake（自编译 llama.cpp 的前提） | **本机未安装**，且 `dl.google.com` 不通，装不上 |
| GitHub 源码 | ⚠️ 网页可达，但 `objects.githubusercontent.com`（release 附件、LFS）**不通** |
| GGUF 模型 | ✅ **反倒能拿到**：ModelScope 有官方 `Qwen/Qwen2.5-1.5B-Instruct-GGUF`（q4_k_m ≈ 1GB） |

**一句话**：模型能下，但没有能加载它的引擎；引擎要么镜像上没有，要么缺工具链自己编。
所以现在没有「下载 LLM」这个动作 —— 缺的是代码与工具链，不是文件。

可选的替代是**接云端大模型 API**（设计里的 `SummaryTier.EXTERNAL` 档），
实现成本低得多，代价是那一部分内容要离开手机、且需要自己的 API Key。

### 0.7.1 修复的三个录音问题

### 签名

自用密钥库 `keystore/shangkele-release.jks`（alias `shangkele`，密码见 `keystore.properties`，该文件不入库）。
**务必自行备份这个 .jks**：丢了之后新版本无法覆盖安装升级。

签名校验：

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\36.0.0\apksigner.bat" verify --verbose --print-certs dist\ShangKeLe-0.1.0-w1-release.apk
```

| 坑 | 现象 | 处理 |
|---|---|---|
| 项目路径含中文（`f:\上课啦`） | AGP 报 `project path contains non-ASCII characters` | 已在 `gradle.properties` 打开 `android.overridePathCheck=true`；测试 worker 另见下条 |
| `C:\Users\<中文用户名>\.gradle` | Gradle 测试 worker 报 `ClassNotFoundException: GradleWorkerMain` | 用 ASCII 目录联接 `F:\ShangKeLe` / `F:\gradle-user-home` 绕开，`build.ps1` 已自动切换 |
| `dl.google.com` 不可达 | 依赖与 build-tools 下载失败（AGP 会尝试自动下载 35.0.0） | 仓库走阿里云镜像（见 `settings.gradle.kts`）；并显式指定 `buildTools = 36.0.0` |
| PowerShell → `.bat` 传带冒号的任务名 | Gradle 收到孤零零一个 `:`，报 `Cannot locate tasks that match ':'` | `build.ps1` 改为交给 `cmd /c` 透传整条命令串 |
| Kotlin 增量编译缓存 | 换过构建路径后出现莫名的 `Unresolved reference` | `.\gradlew.bat clean` 后重编（`build.ps1` 不自动 clean，避免拖慢日常构建） |

**建议**：把工程目录改成纯英文名（如 `F:\ShangKeLe`）可彻底摆脱上面两条路径问题。
当前用目录联接已能正常构建，`F:\ShangKeLe` 与 `f:\上课啦` 指向同一份文件。

真机安装：

```powershell
adb install -r -g app\build\outputs\apk\debug\app-debug.apk
```

> 换机/换目录后，重新创建联接即可：
> `New-Item -ItemType Junction -Path F:\ShangKeLe -Target <工程绝对路径>`
> `New-Item -ItemType Junction -Path F:\gradle-user-home -Target $env:USERPROFILE\.gradle`
